# Plan del proyecto JJ Pega

## 1. Objetivo

Crear una tienda online de stickers JJ Pega con una identidad visual alegre, clara y consistente, permitiendo comprar stickers listos, colecciones por categoría y diseños personalizados.

## 2. Catálogo y tamaños

### Tamaños definidos para el catálogo

| Tamaño | Uso recomendado |
| --- | --- |
| 1.5 pulgadas | Opción pequeña; disponible con PrintEasy PR |
| 2 pulgadas | Volumen y colecciones; tamaño principal para comenzar |
| 2.5 pulgadas | Tamaño intermedio; disponible con PrintEasy PR |
| 3 pulgadas | Sticker protagonista y tamaño estrella |
| 4 pulgadas | Opción premium y personalizados |

La estrategia recomendada es usar 2 pulgadas para colecciones, 3 pulgadas para diseños protagonistas y 4 pulgadas para productos premium o personalizados.

## 3. Precios de venta documentados

El PDF propone estas referencias comerciales:

- 1 sticker: **$8**.

- Los stickers personalizados pueden venderse a un precio mayor porque incluyen el trabajo de diseño.

Los escenarios de ganancia del PDF usan principalmente stickers de 3 pulgadas, pero algunas cifras aparecen con formato incompleto en la extracción del documento. Deben confirmarse antes de convertirlas en precios definitivos del catálogo.

## 9. Banco de ideas para stickers con frases

El documento `Notes_260914_123909.pdf` reúne ideas creativas para desarrollar stickers con frases originales, personajes y elementos visuales propios de JJ Pega. Este banco servirá para crear diseños, colecciones y packs.

### Categorías creativas

1. **Humor cotidiano / Relatable**
   - Situaciones diarias, cansancio, productividad, café, sueño y batería social.
   - Ejemplos: “Estoy bien… en teoría”, “Mi cerebro tiene 47 pestañas abiertas y ninguna carga” y “Aquí sobreviviendo con estilo”.

2. **Café, bebidas y mañanas**
   - Tazas, espresso, iced coffee, matcha, frappés y personajes con sueño.
   - Ejemplos: “Café primero, decisiones después”, “Mi taza tiene más estabilidad que yo” y “Hoy estoy a dos sorbos de ser funcional”.

3. **Motivación con personalidad**
   - Mensajes positivos, pero naturales, divertidos y sin tono corporativo.
   - Ejemplos: “Despacio también es avanzar”, “Tu ritmo también cuenta” y “Mi progreso no necesita presentación PowerPoint”.

4. **Actitud, confianza y Sassy**
   - Frases de identidad, límites, estilo y seguridad personal.
   - Ejemplos: “Demasiado yo para ser otra persona”, “Mi paz tiene límites” y “No soy complicada, soy de configuración avanzada”.

5. **Animales con problemas de adultos**
   - Ranas, gatos, perros, perezosos, osos, nutrias y otros animales adorables con frases inesperadas.
   - Ejemplos: “Pequeña rana, grandes pendientes”, “Mi comité interno votó por dormir” y “Voy lento, pero con intención decorativa”.

6. **Cultura, Caribe y Good Vibes**
   - Sol, playa, cafecito, sazón, humedad, chinchorro y energía caribeña.
   - Ejemplos: “Modo isla: activado”, “No estoy sudando, estoy brillando con humedad” y “Mi GPS emocional apunta al chinchorro”.

7. **Frases cortas para stickers pequeños**
   - Especialmente útiles para tamaños de 1.5 a 2.5 pulgadas y para packs.
   - Ejemplos: “Todo chill”, “Pura vibra”, “Sin prisa”, “Modo feliz”, “Respira”, “Sé tú” y “Qué flow”.

### Idiomas

El banco puede desarrollarse en:

- Español.
- Inglés.
- Spanglish.

Las versiones en inglés no deben ser traducciones literales en todos los casos; deben conservar el humor, el giro inesperado y la personalidad de JJ Pega.

Cada diseño debe intentar combinar:

**Frase propia + personaje u objeto + estilo visual propio + nombre de colección.**

La frase no debe aparecer aislada cuando pueda reforzarse con una taza, batería, animal, planta, fruta, estrella, personaje o elemento caribeño.

## 11. Integración de producción para stickers personalizados

El documento `Plan_Integracion_Proveedor_Stickers_API_JJ_Pega.docx` define la arquitectura para producir stickers personalizados bajo demanda, enviar cada pedido directamente al cliente y mantener el CRM como fuente principal de información.

### Objetivo de la integración

- Automatizar pedidos personalizados sin manejar inventario ni envíos manuales.
- Integrar catálogo, tamaños, variantes, archivos de diseño, cotización, pago, producción y tracking.
- Mantener en el CRM la solicitud, aprobación del diseño, cliente, pedido y estados.
- Permitir productos predefinidos y stickers personalizados creados al ordenar.
- Evitar depender de un solo proveedor mediante una capa interna de fulfillment.
- No enviar nada a producción hasta confirmar el pago y aprobar el artwork.

### Proveedor inicial recomendado

**Printify** será el proveedor primario para el MVP, sujeto a validación de productos y API actuales.

Alternativas documentadas:

- **Printful:** segundo proveedor y alternativa inmediata.
- **Prodigi:** evaluación secundaria y posible opción white-label.

La tienda nunca debe comunicarse directamente con estos proveedores. El backend de JJ Pega/CRM debe controlar la integración para proteger las credenciales, validar pagos, aprobar diseños, registrar estados y permitir cambiar de proveedor sin rehacer el checkout.

### Flujo de un pedido personalizado

1. El cliente completa “Crea tu sticker”, sube el archivo y selecciona tamaño, cantidad y acabado.
2. La solicitud se registra mediante el sistema de formularios existente del CRM.
3. El backend valida formato, resolución, dimensiones, transparencia y requisitos de impresión.
4. JJ Pega o una automatización aprueba o rechaza el artwork.
5. El backend calcula producción, envío, margen e impuestos aplicables.
6. El cliente paga en JJ Pega.
7. Con el pago confirmado, se crea la orden de fulfillment.
8. El proveedor imprime, corta, empaca y despacha.
9. Webhooks o polling de respaldo actualizan el estado y el tracking.
10. JJ Pega conserva la atención, historial, reimpresiones y métricas dentro del CRM.

### Fases técnicas

#### Fase 0 - Validación comercial

- Crear cuentas de desarrollador o sandbox.
- Confirmar productos, tamaños, acabados, archivos aceptados, tiempos y destinos.
- Pedir muestras físicas.
- Revisar empaque, branding y opciones white-label.

#### Fase 1 - Capa interna de fulfillment

- Crear una interfaz propia `FulfillmentProvider`.
- Encapsular Printify en un adaptador `PrintifyProvider`.
- Mantener las API keys únicamente en backend o secret manager.
- Usar sandbox o simulación antes de producción.

#### Fase 2 - Catálogo y variantes

- Relacionar cada SKU interno con el producto y variante del proveedor.
- Guardar el mapping en base de datos o configuración administrativa.
- No depender de IDs del proveedor dentro de React.
- Sincronizar disponibilidad y detectar variantes descontinuadas.

#### Fase 3 - Artwork personalizado

- Reutilizar el sistema de uploads existente del CRM.
- Crear una versión de producción separada del archivo original.
- Validar resolución, DPI, dimensiones, transparencia, bleed y área segura.
- Guardar hash, dimensiones, MIME, versión y estado de aprobación.

#### Fase 4 - Cotización y checkout

- Calcular el shipping usando la dirección final del cliente.
- Usar la fórmula: **costo de producción + shipping + fees + impuestos + margen JJ Pega + reserva de incidencias**.
- Separar el shipping cobrado al cliente del costo real del proveedor.
- Guardar un snapshot de la cotización usada durante el checkout.
- Bloquear el precio por un período corto para evitar discrepancias.

#### Fase 5 - Orden, producción y tracking

- Crear primero el estado interno `pending_fulfillment`.
- Usar idempotency key o referencia externa para evitar duplicados.
- Guardar `provider_order_id` y snapshot del payload enviado.
- Preferir webhooks para actualizar estados y usar polling como respaldo.
- Registrar carrier, número de tracking, URL y eventos de envío.

#### Fase 6 - CRM y experiencia del cliente

- Mostrar el estado del pedido en el CRM y en la cuenta del cliente.
- Automatizar avisos de “en producción”, “enviado” y “entregado”.
- Mantener notas, soporte, reimpresiones y reclamos en el CRM.

### Estados internos del pedido

`draft` → `artwork_review` → `quoted` → `awaiting_payment` → `paid` → `pending_fulfillment` → `submitted` → `in_production` → `shipped` → `delivered`

Estados de error separados:

- `artwork_rejected`
- `payment_failed`
- `provider_failed`
- `address_issue`
- `canceled`
- `refunded`

### Datos mínimos que debe conservar el sistema

**Artwork:** archivo original, archivo de producción, ancho, alto, DPI, MIME, hash, estado de aprobación y fecha de aprobación.

**Mapping de fulfillment:** producto interno, proveedor, producto externo, variante, proveedor de impresión y estado activo.

**Orden:** orden del CRM, cliente, total, moneda, estado de pago, estado de fulfillment y proveedor.

**Orden del proveedor:** ID externo, referencia, snapshot del payload, costo de proveedor, costo de envío y fecha de envío a producción.

**Envío:** carrier, número de tracking, URL, fecha de despacho, fecha de entrega y último evento.

### Seguridad y confiabilidad

- Nunca exponer API keys en React, Vite o el navegador.
- Validar MIME, extensión, tamaño y dimensiones del archivo.
- Firmar y deduplicar webhooks cuando el proveedor lo permita.
- No producir antes del pago confirmado y artwork aprobado.
- Guardar snapshots para investigar diferencias de precio, archivo u orden.

### Pruebas obligatorias

- SKU y variante correctos.
- Artwork válido, orientado y con resolución adecuada.
- Shipping correcto para Puerto Rico y Estados Unidos continental.
- Dirección inválida bloqueada antes de producción.
- Pago fallido sin orden enviada al proveedor.
- Reintentos sin duplicar órdenes.
- Fallos del proveedor visibles y reintentables en el CRM.
- Tracking visible para JJ Pega y el cliente.
- Cancelación dentro de la ventana permitida.
- Pedido físico de muestra revisado antes del lanzamiento.

### Estrategia de lanzamiento

- **Sandbox:** integración completa sin fulfillment real.
- **Muestras:** 3 a 5 pedidos internos a distintos destinos y productos.
- **Beta limitada:** 1 o 2 tipos de sticker con un proveedor.
- **Producción:** apertura gradual con monitoreo de errores y margen real.
- **Multi-proveedor:** agregar Printful o Prodigi si mejora costo, cobertura o tiempos.
